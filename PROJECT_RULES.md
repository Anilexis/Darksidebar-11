# Регламент и правила проекта Darksidebar-11

Данные правила обязательны для выполнения AI-ассистентами и разработчиками при любых изменениях в проекте.

---

## 1. Семантическое версионирование и релизный цикл

При **любом** исправлении багов, рефакторинге или добавлении функционала:
1. **Повышение версии (SemVer):**
   - `PATCH` (1.0.x) — исправление ошибок, фиксы верстки, кодировок, скриптов.
   - `MINOR` (1.x.0) — новые фичи, виджеты, новые параметры конфигурации.
   - `MAJOR` (x.0.0) — кардинальная смена архитектуры.

2. **Сборка релизного пакета:**
   - Всегда компилировать плагин и упаковывать скин:
     ```powershell
     pwsh -File ./build-package.ps1 -Version "<НОВАЯ_ВЕРСИЯ>"
     ```
   - Пакет генерируется в `dist/Darksidebar-11-v<НОВАЯ_ВЕРСИЯ>.rmskin`.

3. **Обновление Scoop-манифеста (`bucket/darksidebar-11.json`):**
   - Обновить поля:
     - `"version"`: актуальная версия (без префикса `v`).
     - `"url"`: ссылка на релиз GitHub `https://github.com/Anilexis/Darksidebar-11/releases/download/v<ВЕРСИЯ>/Darksidebar-11-v<ВЕРСИЯ>.rmskin`.
     - `"hash"`: точный SHA256 хеш релизного файла с GitHub Releases.

4. **Фиксация в Git и GitHub:**
   - Закоммитить все изменения по формату Conventional Commits (`fix: ...`, `feat: ...`, `refactor: ...`).
   - Создать тег версии: `git tag v<НОВАЯ_ВЕРСИЯ>`.
   - Запушить изменения и тег в удаленный репозиторий:
     ```bash
     git push origin main
     git push origin v<НОВАЯ_ВЕРСИЯ>
     ```
   - Дождаться сборки релиза на GitHub Actions и синхронизировать окончательный SHA256 хеш в Scoop-манифесте.

## 2. Строгая деперсонализация репозитория и релизов (КРИТИЧЕСКИ ВАЖНО)

В публичном Git-репозитории и в релизных пакетах `.rmskin` **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** сохранять персональные данные разработчика:
1. **Мониторы:** в репозитории и релизах монитор по умолчанию — `Primary` (`MonitorFallbackDev=\\.\DISPLAY1`, `MonitorFriendlyName=Primary`, `MonitorTargetId=`). Никаких `SyncMaster` / `SAM0247` / `DISPLAY2` в публичном коде!
2. **Диски:** в `disks-generated.inc` и `disks-vars.inc` должен быть нейтральный шаблон **только для диска C:** (`DisksCount=1`). Никаких дисков разработчика (D:, E:, G:, T:, W: с их метками). При установке у нового пользователя `update-disks.ps1` автоматически сгенерирует диски его системы.
3. **Город и координаты:** нейтральный дефолт — `London` (51.5074, -0.1278, GB), `FirstRunDone=0`. На чистой системе `first-run.ps1` выполнит первичное определение под нового пользователя.
4. **Кэши:** `weather-data.inc`, `hardware-data.inc` и `holidays.lua` в репозитории и релизах должны быть чистыми (только заголовки `[Variables]`).
5. **Где хранятся персональные настройки:** Персональные настройки разработчика (город Тюмень, монитор SyncMaster, личные диски) живут **ИСКЛЮЧИТЕЛЬНО** в локальной рабочей папке пользователя:
   `%USERPROFILE%\Documents\Rainmeter\Skins\Darksidebar-11\`
   При синхронизации репозитория с папкой `Documents` локальный файл `Settings.inc` и личные диски разработчика **не перезаписываются**.

## 3. Кодировки файлов и работа с кириллицей

1. **Кодировка Windows-1251 (CP1251) для скина и настроек:**
   - Rainmeter на русскоязычной Windows работает в режиме ANSI (`GetPrivateProfileStringA` / CP1251).
   - Все конфигурационные файлы скина (`.ini`, `.inc`), содержащие кириллические символы (включая `Sidebar.ini`, `Settings.ini`, `Settings.inc`, `Languages/Russian.inc`, кэш-файлы), **ОБЯЗАНЫ сохраняться в кодировке Windows-1251 (CP1251)** (`[System.Text.Encoding]::GetEncoding(1251)`).
   - **СТРОГО ЗАПРЕЩЕНО** сохранять `Settings.inc` в UTF-8. Это приводит к mojibake-кракозябрам вида `РўСЋРјРµРЅСЊ` вместо «Тюмень», а UTF-8 BOM ломает считывание секции `[Variables]`.

## 4. Синхронизация с рабочей средой пользователя

При внесении изменений в файлы `Skins/Darksidebar-11/`:
1. Скрипты (`@Resources\Scripts\*`), оформление и код скина копируются в:
   ```
   $env:USERPROFILE\Documents\Rainmeter\Skins\Darksidebar-11\
   ```
   (За исключением перезаписи файла персональных настроек пользователя `Settings.inc` и сгенерированных дисков `disks-generated.inc`!).
2. Для применения изменений посылать команду обновления Rainmeter:
   ```powershell
   & "C:\Program Files\Rainmeter\Rainmeter.exe" !RefreshApp
   ```

## 5. Защита пользовательских настроек при обновлении (Scoop и .rmskin)

При обновлении скина существующие пользовательские настройки и дисковая топология **НИКОГДА НЕ ДОЛЖНЫ СБРАСЫВАТЬСЯ**:
1. **Шаблоны по умолчанию вместо живых настроек в пакете `.rmskin`:**
   - В публичный пакет `.rmskin` поставляется нейтральный шаблон `Settings.default.inc` (`FirstRunDone=0`, London, Primary monitor).
   - Файл `Settings.inc` **НЕ ДОЛЖЕН** находиться внутри архива `.rmskin`!
   - В `Rainmeter.tag` всегда устанавливается `Merge=1` (ни в коем случае не `Merge=0`!).
   - Благодаря `Merge=1` и отсутствию `Settings.inc` в архиве, установщик Rainmeter (`SkinInstaller.exe`) обновляет код скина, но оставляет локальный `Settings.inc` пользователя нетронутым.
2. **Защита дисковой топологии и кэшей:**
   - Файлы `disks-generated.inc` и `disks-vars.inc` **НЕ ДОЛЖНЫ** паковаться в `.rmskin`.
   - Вместо них поставляются `disks-generated.default.inc` и `disks-vars.default.inc`.
   - Существующая топология дисков пользователя сохраняется при любых обновлениях.
3. **Безопасное обновление через Scoop (`bucket/darksidebar-11.json`):**
   - В скрипте распаковщика установлен фильтр защиты: файлы `Settings.inc` и `Cache\disks-*` пропускаются при распаковке, если они уже существуют в системе пользователя.
   - Выполняется плавный мерж новых ключей из `Settings.default.inc` в `Settings.inc` в кодировке CP1251 без перезаписи существующих пользовательских значений.
4. **Защитный Guard в `first-run.ps1`:**
   - В начале `first-run.ps1` обязательно проверяется `FirstRunDone=1`.
   - Если `FirstRunDone=1`, скрипт немедленно прерывает выполнение, гарантируя, что город, координаты, язык и монитор пользователя не будут перезаписаны повторной автодетекцией при обновлениях.
5. **Внешнее персистентное хранилище (`%APPDATA%\Rainmeter\Darksidebar11-Config`):**
   - Настройки пользователя (`Settings.inc`) и дисковая топология (`disks-generated.inc`, `disks-vars.inc`) зеркалируются в независимое персистентное хранилище `%APPDATA%\Rainmeter\Darksidebar11-Config\`.
   - При старте `first-run.ps1` и в установщике Scoop первым делом проверяется наличие данных в персистентном хранилище; при наличии они восстанавливаются без сброса.
   - В `uninstaller.script` Scoop **СТРОГО ЗАПРЕЩЕНО** удалять рабочую папку скина (`Remove-Item $skinsDest -Recurse -Force`). Деинсталлятор Scoop обязан только создать резервную копию в персистентное хранилище и деактивировать скин в Rainmeter.

## 6. Регламент бета-ветки и бета-релизов (Beta Workflow)

1. **Ветвление:**
   - Ветка `main` содержит исключительно стабильный проверенный код.
   - Ветка `beta` предназначена для разработки новых фич, масштабного рефакторинга и тестирования.

2. **Версионирование бета-версий:**
   - Формат тега: `v<ВЕРСИЯ>-beta.<НОМЕР>` (например, `v1.1.0-beta.1`).
   - GitHub Actions (`workflows/release.yml`) автоматически определяет суффикс `-beta` и публикует релиз со статусом **Pre-release** (`prerelease: true`).

3. **Scoop-каналы:**
   - Стабильный пакет: `bucket/darksidebar-11.json` (следит только за non-prerelease `latest`).
   - Бета-пакет: `bucket/darksidebar-11-beta.json` (следит за пре-релизами с тегом `-beta`).
   - Пользователи стабильной версии не получают бета-обновления автоматически при `scoop update`.
   - Переключение на бета-канал:
     ```powershell
     scoop uninstall darksidebar-11
     scoop install darksidebar-11-beta
     ```
   - Возврат на стабильный канал:
     ```powershell
     scoop uninstall darksidebar-11-beta
     scoop install darksidebar-11
     ```
   - Пользовательские настройки (`Settings.inc`, диски, город) сохраняются в `%APPDATA%\Rainmeter\Darksidebar11-Config` и переносятся без потерь.

4. **Слияние беты в стабильную ветку:**
   - Когда бета-версия оттестирована и готова к релизу, изменения из `beta` вливаются в `main`:
     ```bash
     git checkout main
     git merge --no-ff beta
     ```
   - Выпускается стабильный тег `v<ВЕРСИЯ>` (без суффикса `-beta`).
   - Обновляется основной манифест `bucket/darksidebar-11.json`.
